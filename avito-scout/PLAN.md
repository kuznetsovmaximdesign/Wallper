# Avito Scout — план (на согласование)

> **Отдельный проект.** Живёт только в папке `avito-scout/` и не связан с Wallper.
> Единственное касание снаружи — строка `avito-scout/**` в `paths-ignore` у
> `.github/workflows/android.yml`, чтобы коммиты сюда не запускали Android-сборку.
> Перенос в свой репозиторий: `git subtree split --prefix=avito-scout -b avito-scout`
> → push в новый репо (история сохранится), затем удалить папку и эту строку здесь.

## 1. Что делает сервис

Веб-сервис (адаптивный, телефон + десктоп, ставится как PWA), один пользователь — вы.

1. **Задача** — например «Сборка кухни», с описанием, фото и критериями.
2. **Где искать** — адрес/точка на карте + радиус (км), *или* готовая ссылка поиска
   Авито с вашими фильтрами (можно несколько).
3. **По чему искать** — по умолчанию запросы составляет ИИ из описания задачи
   («нужен септик на участок 10 соток» → «монтаж септика», «установка септика под ключ»,
   «автономная канализация», …) и показывает их списком: можно одним нажатием
   подтвердить, убрать лишнее или дописать своё. Затем ИИ отсеивает нерелевантные
   объявления (продажа товаров, другие услуги и т. п.). Ваши пометки «подходит / нет»
   учитываются в следующих поисках по этой теме.
4. **Критерии** — рейтинг ≥ X, отзывов ≥ N, опционально: частник/компания,
   «на Авито с …», подтверждённые документы, цена «от/до».
5. **Таблица исполнителей** — одна строка = одна учётка (не объявление):
   имя, рейтинг, число отзывов, на Авито с, все его найденные объявления, цены,
   расстояние, ссылка на профиль, статус переписки. Сортировка, фильтры, экспорт в
   Excel/CSV, ручные пометки («избранное», «не подходит»).
6. **Рассылка** — выбираете исполнителей → сервис пишет каждому по шаблону задачи;
   если фото нельзя приложить к первому сообщению — отправляет после первого ответа.
   Ответы видны в сервисе, статус в таблице: *не писали → отправлено → ответил →
   фото отправлено → договорились / отказ*.

### Темы (проекты)

Сервис хранит темы — «Забор», «Септик», … У каждой своё описание, фото, запросы,
критерии, таблица исполнителей и переписки. К старой теме можно вернуться:
повторный поиск покажет только новых исполнителей. Если исполнитель уже встречался
в другой теме (например, делает и заборы, и септики), это видно в карточке.

### Переписка «как человек»

- Первое сообщение и ответы пишет ИИ по контексту задачи — каждый раз разными
  словами, без шаблонного «Здравствуйте, интересует услуга…», с паузами как у
  человека (минуты, а не секунды; ночью не пишет).
- **Просят телефон** — вежливо отвечаем, что удобнее продолжить в чате Авито,
  и сразу задаём следующий вопрос по делу, чтобы разговор не застревал.
- **Шаблонные ответы исполнителей** (автоответ Авито, «звоните», «пишите в
  WhatsApp», «цена от …, всё по телефону») — распознаём и отвечаем по сути: уточняем
  цену, сроки, опыт, просим фото работ.
- ИИ **не соглашается** на цену, дату, адрес и предоплату — такие моменты он
  передаёт вам (уведомление), и вы отвечаете сами или одобряете черновик.
- Режим на старте: ИИ готовит ответ → вы одобряете в один тап. Когда тексты
  устроят — можно включить автоответы для простых ситуаций.

## 2. Ключевые ограничения Авито (честно)

| Вопрос | Реальность | Что делаем |
| --- | --- | --- |
| Публичный API поиска | Нет. Официальный API Авито — для продавцов (свои объявления, свои чаты). | Поиск через браузер-робота (Playwright) по страницам сайта. |
| Антибот | Авито блокирует зарубежные и «серверные» IP, показывает капчу при частых запросах. | Сервер/прокси с российским IP, медленный темп, кэш; капча → уведомление вам. |
| Написать исполнителю | Новый чат создаётся только с сайта/приложения покупателем; через API — нельзя. | Робот работает под **вашей** учёткой Авито (вход один раз, сессия хранится). |
| Фото в первом сообщении | Нужно проверить на этапе 0. | Правило «фото сразу, если можно, иначе — после ответа». |
| Антиспам | Массовые одинаковые сообщения → ограничение/бан учётки. | Лимит новых чатов в день (старт ~10–15), паузы, вариации текста, ручное подтверждение пачки. |
| Правила Авито | Автоматический сбор и рассылка запрещены пользовательским соглашением — риск блокировки учётки. | Темп «как человек», лимиты; рекомендую отдельную учётку для рассылок. |

## 3. Дедупликация

Ключ — **ID профиля продавца** из ссылки `avito.ru/user/<id>/profile` (или
`/brands/<id>`): это точнее, чем имя (имена повторяются, «Александр» — тысячи).
Запасной ключ, если ID не удалось достать: имя + рейтинг + число отзывов +
«на Авито с». Все объявления одной учётки сворачиваются в одну строку.
Уже отклонённые/написанные исполнители помечаются и в новых поисках не всплывают
повторно как новые.

## 4. Архитектура

Один процесс на Python 3.12 (на мини-ПК уже есть Python и Playwright, деплой
повторяет Neiron: `pytest` перед перезапуском):

```
avito-scout/
  avito_scout/  веб (FastAPI + шаблоны, адаптивно), робот (Playwright), разбор, SQLite
  tests/        pytest, HTML-образцы выдачи
  deploy/       systemd-служба, таймер автообновления, update.sh, sudoers
```

- **БД:** SQLite (одного пользователя хватает; потом легко Postgres).
- **ИИ:** Claude API — расширение запросов, оценка релевантности объявления,
  вариации текста сообщения.
- **Хостинг:** ваш мини-ПК дома (решено) — домашний российский IP, антибот к нему
  лоялен, прокси не нужен. systemd-служба `avito-scout` + таймер автообновления.
- **Доступ с телефона/ноутбука:** Cloudflare Tunnel или Tailscale — HTTPS без
  проброса портов на роутере; вход по паролю.
- **Учётка Авито:** отдельная, только для этого сервиса (решено).
- **Уведомления:** Telegram-бот — «исполнитель ответил», «нужна капча», «поиск готов».

## 6. Решения

| Вопрос | Решение |
| --- | --- |
| Где работает | Мини-ПК дома |
| Учётка Авито | Отдельная |
| Телефон просят | Просим продолжить в чате Авито |

## 7. Мини-ПК (проверено 27.10)

Ubuntu 24.04, Intel N100, 15 ГБ ОЗУ, 336 ГБ свободно, работает 24/7, монитора нет
(есть Xvfb). Chromium для Playwright уже скачан, Node 22 и Python 3.12 есть.

- **Авито отдал curl'у 429 «Доступ ограничен: проблема с IP»** с домашнего IP
  (Истра). Вероятная причина — отпечаток curl, а не IP. Первый шаг этапа 0 —
  один заход настоящим Chromium.
- Роботу ходить **без прокси** (в шелле задан HTTPS_PROXY → Амстердам).
- IP общий с семьёй: если Авито его пометит, капчу начнут видеть и домашние.
  Запасной план — отдельный выход для робота (USB-модем 4G со своей SIM или
  мобильный прокси).
- **Деплой** как у Neiron: пользователь `avito`, sparse-клон `avito-scout/` в
  `/opt/avito-scout`, таймер раз в минуту, read-only deploy key, рестарт только
  при изменениях в папке. Порт **8793**.
- **Отладка:** `claude remote-control` в tmux под `max`, без ANTHROPIC_API_KEY,
  режим `acceptEdits`.
- **Капча:** на этапе 0 — x11vnc + noVNC через Tailscale; в продукте —
  скриншот капчи прямо в веб-интерфейсе.
- **Telegram:** отдельный бот.
- **ИИ в сервисе:** отдельный ключ Claude API с лимитом расходов (подписка —
  для Claude Code, не для фоновых программ).
